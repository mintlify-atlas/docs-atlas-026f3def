AuthKit React Router resolves its configuration from three sources, applied in the following priority order:

1. **Programmatic values** supplied via `configure()` at startup.
2. **Environment variables** prefixed with `WORKOS_`, read at runtime from `process.env` (or a custom source you register).
3. **Default values** for optional settings.

The most common approach is to set environment variables and let the library pick them up automatically. Use `configure()` when you need override values in code, or when you are deploying to a runtime that does not expose `process.env`.

## Environment Variables

Create a `.env.local` file at the project root (never commit it to source control):

```bash .env.local
WORKOS_CLIENT_ID="client_..."          # required — WorkOS Client ID
WORKOS_REDIRECT_URI="http://localhost:5173/callback"  # required — OAuth callback URL
WORKOS_COOKIE_PASSWORD="<your-32-character-password>" # required — cookie encryption key
WORKOS_API_KEY="sk_test_..."           # optional — omit for public-client (keyless) mode

# Optional overrides
WORKOS_COOKIE_NAME="wos-session"
WORKOS_API_HTTPS="true"
WORKOS_COOKIE_MAX_AGE="34560000"
WORKOS_API_HOSTNAME="api.workos.com"
WORKOS_API_PORT=""
WORKOS_ISSUER=""
```

### Configuration Reference

| Option | Environment Variable | Default | Required | Description |
|---|---|---|---|---|
| `clientId` | `WORKOS_CLIENT_ID` | — | Yes | Your WorkOS Client ID, retrieved from the WorkOS dashboard. |
| `apiKey` | `WORKOS_API_KEY` | — | No | Your WorkOS API Key. Required for feature flags and WorkOS management APIs. Omit for [public-client mode](#public-client-keyless-mode). |
| `redirectUri` | `WORKOS_REDIRECT_URI` | — | Yes | The OAuth callback URL registered in your WorkOS dashboard. Must match exactly. |
| `cookiePassword` | `WORKOS_COOKIE_PASSWORD` | — | Yes | Password used to encrypt the session cookie with iron-session. Must be at least 32 characters. |
| `cookieName` | `WORKOS_COOKIE_NAME` | `wos-session` | No | Name of the session cookie set on the browser. |
| `apiHttps` | `WORKOS_API_HTTPS` | `true` | No | Whether to use HTTPS when communicating with the WorkOS API. |
| `cookieMaxAge` | `WORKOS_COOKIE_MAX_AGE` | `34560000` (400 days) | No | Maximum age of the session cookie in seconds. The actual session lifetime is governed by the access and refresh token expiry, so a long cookie age is safe. |
| `apiHostname` | `WORKOS_API_HOSTNAME` | `api.workos.com` | No | Hostname of the WorkOS API. Override when using a proxy or a self-hosted WorkOS environment. |
| `apiPort` | `WORKOS_API_PORT` | — | No | Port to use when calling the WorkOS API. Typically not needed in production. |
| `issuer` | `WORKOS_ISSUER` | API origin | No | Expected `iss` claim of WorkOS access tokens. Accepts a single value or a comma-separated list of accepted issuers. Defaults to the configured API origin (e.g. `https://api.workos.com`). |

## Programmatic Configuration

Import `configure` and call it early in your application's lifecycle — for example in `app/root.tsx` or a dedicated `app/lib/auth.ts` module that is imported before any route loaders run.

```typescript
import { configure } from '@workos-inc/authkit-react-router';

configure({
  clientId: 'client_1234567890',
  redirectUri: 'http://localhost:5173/callback',
  cookiePassword: 'your-secure-cookie-password-min-32-chars',

  // Optional settings
  apiKey: 'sk_test_1234567890',        // omit for public-client (keyless) mode
  cookieName: 'my-custom-cookie-name',
  apiHttps: true,
  cookieMaxAge: 60 * 60 * 24 * 30,    // 30 days
  apiHostname: 'api.workos.com',
});
```

Programmatic values take the highest priority, overriding any environment variables that are also set. This makes `configure()` useful for test environments where you want deterministic values regardless of the process environment.

## Custom Environment Source

For runtimes where `process.env` is unavailable — such as Deno or edge functions — you can register a custom function that `configure` will call instead of reading `process.env`:

```typescript
import { configure } from '@workos-inc/authkit-react-router';

// Provide a custom environment source
configure((key) => Deno.env.get(key));

// Or combine explicit values with a custom source
configure({ clientId: 'client_1234567890' }, (key) => Deno.env.get(key));
```

The function receives the full `WORKOS_`-prefixed environment variable name (e.g. `WORKOS_CLIENT_ID`) and should return the corresponding value as a string, or `undefined` if the variable is not set.

<Warning>
  Support for custom environment sources is designed to enable non-Node.js runtimes such as Deno or Edge functions, but this functionality has not been extensively tested yet. If you use AuthKit in these environments you may encounter unexpected issues. Feedback and contributions from users testing in these environments are very welcome.
</Warning>

## Configuration Priority

When the library resolves a configuration value, it checks sources in this order:

1. **Programmatic `configure()` values** — the highest priority. Explicit values here override everything else.
2. **Environment variables** — the `WORKOS_`-prefixed variables from `process.env` (or your custom source). Checked after programmatic values.
3. **Default values** — built-in defaults for optional settings such as `cookieName: 'wos-session'`, `apiHttps: true`, `cookieMaxAge: 34560000`, and `apiHostname: 'api.workos.com'`.

If a required setting (`clientId`, `redirectUri`, `cookiePassword`) is missing from all three sources, the library throws an error when that value is first accessed.

## Public Client (Keyless) Mode

If your service only needs to sign users in and should not hold a WorkOS secret key, omit `WORKOS_API_KEY` entirely. AuthKit will operate as an OAuth 2.0 public client, protecting the code exchange with PKCE instead of a client secret:

```bash .env.local
WORKOS_CLIENT_ID="client_..."
WORKOS_REDIRECT_URI="http://localhost:5173/callback"
WORKOS_COOKIE_PASSWORD="<your-32-character-password>"
```

<Note>
  **What works in keyless mode:** `getSignInUrl`, `getSignUpUrl`, `authLoader` (callback + code exchange), `authkitLoader` (including automatic token refresh), `withAuth`, `refreshSession`, `switchToOrganization`, `saveSession`, and `signOut`.

  **What requires an API key:** `getFeatureFlagsRuntimeClient()` — throws `Feature flags require a WorkOS API key` in keyless mode. Direct WorkOS management API calls via `getWorkOS()` (e.g. `organizations.*`, `userManagement.getUser`) — the WorkOS SDK rejects them with an `ApiKeyRequiredException`.
</Note>

For a full guide to keyless mode, including PKCE mechanics and dashboard configuration, see [Public Client Mode](/guides/public-client-mode).

## Debugging

<Tip>
  To inspect every resolved configuration value at once, import and call `getFullConfig()`. It returns a plain object with all current settings — useful when you need to confirm which source a value came from. Never log the output in production as it includes `cookiePassword` and `apiKey`.
</Tip>

To enable per-request debug logging in your loaders, pass `debug: true` to `authkitLoader`:

```typescript
import { authkitLoader } from '@workos-inc/authkit-react-router';
import { type LoaderFunctionArgs } from 'react-router';

export const loader = (args: LoaderFunctionArgs) =>
  authkitLoader(args, { debug: true });
```

When `debug` is enabled, AuthKit logs session validation outcomes, token-refresh events, and feature-flag fallbacks to the server console.
