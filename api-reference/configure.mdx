---
title: "configure — Set Up AuthKit React Router Programmatically"
sidebarTitle: "configure"
description: "configure() sets AuthKit React Router options programmatically, overriding environment variables. Accepts an options object, a custom env source, or both."
---

`configure` sets AuthKit React Router options at runtime from code rather than environment variables. Use it when you need to supply configuration dynamically — for example when bootstrapping from a secret manager, running in a non-Node.js runtime such as Deno or Edge functions, or writing tests that need isolated config values.

## Import

```ts
import { configure } from '@workos-inc/authkit-react-router';
```

## Signatures

<Tabs>
  <Tab title="Config object">
    ```ts
    configure(config: Partial<AuthKitConfig>): void
    ```

    Pass a plain object with any subset of the `AuthKitConfig` fields. Unset fields continue to fall through to environment variables and built-in defaults.
  </Tab>

  <Tab title="Custom env source">
    ```ts
    configure(source: (key: string) => any): void
    ```

    Pass a function that receives an uppercase `WORKOS_*` environment variable name and returns its value. Use this overload to read config from runtimes that don't expose `process.env`, such as `Deno.env.get`.
  </Tab>

  <Tab title="Both">
    ```ts
    configure(config: Partial<AuthKitConfig>, source: ValueSource): void
    ```

    Combine an explicit config object with a custom env source. The source is queried for keys not found in the environment, and built-in defaults fill the rest.

    ```ts
    // ValueSource can also be a plain object:
    type ValueSource = Record<string, any> | ((key: string) => any);
    ```
  </Tab>
</Tabs>

## Parameters

<ParamField body="config" type="Partial<AuthKitConfig>" optional>
  A partial configuration object. Fields provided here take effect after environment variable resolution. See [Config Options](#config-options) for the full list of fields.
</ParamField>

<ParamField body="source" type="(key: string) => any | Record<string, any>" optional>
  A custom environment variable source. When provided as a function, it is called with the uppercase `WORKOS_*` key name (e.g. `"WORKOS_CLIENT_ID"`) and must return the corresponding value. Can also be a plain object whose keys are the `WORKOS_*` variable names. This source replaces `process.env` as the environment variable backend.
</ParamField>

## Config Options

| Field | Environment Variable | Type | Default | Required | Description |
|---|---|---|---|---|---|
| `clientId` | `WORKOS_CLIENT_ID` | `string` | — | Yes | Your WorkOS Client ID |
| `apiKey` | `WORKOS_API_KEY` | `string` | — | No | Your WorkOS API key. Required for feature flags and management APIs. Omit for [public client mode](/api-reference/get-feature-flags-runtime-client#warning). |
| `redirectUri` | `WORKOS_REDIRECT_URI` | `string` | — | Yes | The callback URL configured in your WorkOS dashboard |
| `cookiePassword` | `WORKOS_COOKIE_PASSWORD` | `string` | — | Yes | Password used to encrypt the session cookie. Must be at least 32 characters. |
| `cookieName` | `WORKOS_COOKIE_NAME` | `string` | `"wos-session"` | No | Name of the session cookie |
| `apiHttps` | `WORKOS_API_HTTPS` | `boolean` | `true` | No | Whether to use HTTPS for WorkOS API calls |
| `cookieMaxAge` | `WORKOS_COOKIE_MAX_AGE` | `number` | `34560000` (400 days) | No | Maximum age of the session cookie in seconds |
| `apiHostname` | `WORKOS_API_HOSTNAME` | `string` | `"api.workos.com"` | No | WorkOS API hostname |
| `apiPort` | `WORKOS_API_PORT` | `number` | — | No | Port to use for WorkOS API calls |
| `issuer` | `WORKOS_ISSUER` | `string \| string[]` | API origin | No | Expected `iss` claim of WorkOS access tokens. Use a comma-separated string in env vars to supply multiple accepted values. |

<Note>
  `cookiePassword` must be at least 32 characters long. `configure` throws immediately if a shorter value is supplied.
</Note>

<Note>
  `apiKey` is intentionally optional. Without it, AuthKit runs as a PKCE public client (sign-in only). See [Public client mode](#public-client-keyless-mode) below.
</Note>

## Priority

Configuration values are resolved in the following order:

1. **Environment variables** — `WORKOS_*` variables from the active source (defaults to `process.env`). These take highest precedence at runtime.
2. **Programmatic config** — values passed directly to `configure()` as an object. Applied after env var lookup.
3. **Built-in defaults** — e.g. `cookieName: "wos-session"`, `apiHttps: true`, `cookieMaxAge: 34560000` (400 days), `apiHostname: "api.workos.com"`.

<Note>
  Environment variables always win over programmatic config values. If you need a value to take absolute precedence, avoid setting the corresponding `WORKOS_*` environment variable.
</Note>

## Examples

### Confidential client (with API key)

A confidential client holds a WorkOS API key on the server. This unlocks feature flags (`getFeatureFlagsRuntimeClient`) and direct WorkOS management API calls via `getWorkOS()`.

```ts
import { configure } from '@workos-inc/authkit-react-router';

configure({
  clientId: 'client_1234567890',
  redirectUri: 'http://localhost:5173/callback',
  cookiePassword: 'your-secure-cookie-password-min-32-chars',
  apiKey: 'sk_test_1234567890',
  // Optional overrides
  cookieName: 'my-custom-cookie',
  apiHttps: true,
  cookieMaxAge: 60 * 60 * 24 * 30, // 30 days
});
```

### Public client (keyless, no API key)

Omit `apiKey` to run AuthKit as a PKCE public client. Sign-in, callback, session refresh, and sign-out all work. Feature flags and WorkOS management APIs are unavailable.

```ts
import { configure } from '@workos-inc/authkit-react-router';

configure({
  clientId: 'client_1234567890',
  redirectUri: 'http://localhost:5173/callback',
  cookiePassword: 'your-secure-cookie-password-min-32-chars',
});
```

### Custom environment source (Deno)

Supply a function to read environment variables from non-Node.js runtimes.

```ts
import { configure } from '@workos-inc/authkit-react-router';

configure((key) => Deno.env.get(key));
```

### Combined: explicit values and custom source

Provide some values explicitly while delegating the rest to a custom source.

```ts
import { configure } from '@workos-inc/authkit-react-router';

configure(
  { clientId: 'client_1234567890' },
  (key) => Deno.env.get(key),
);
```

## Public client (keyless) mode

If your service only signs users in and should not hold a WorkOS API key, leave `WORKOS_API_KEY` unset (or omit `apiKey` from `configure`). AuthKit then runs as an OAuth PKCE public client.

What works without a key: sign-in and sign-up URLs, the callback (`authLoader`), `authkitLoader` (including automatic refresh), `withAuth`, `refreshSession`, `switchToOrganization`, `saveSession`, and `signOut`.

What requires a key:
- Feature flags — `getFeatureFlagsRuntimeClient()` throws in keyless mode.
- Direct WorkOS management calls through `getWorkOS()`, such as `organizations.*` or `userManagement.getUser`.

<Warning>
  The WorkOS Node SDK falls back to `process.env.WORKOS_API_KEY` when no key is configured programmatically. If that variable is set in the server's environment, a key is always in play even when you use a custom value source with `configure()`. To run fully keyless, make sure `WORKOS_API_KEY` is absent from the process environment.
</Warning>

## `getConfig`

`getConfig` is the companion accessor that reads a single resolved configuration value by key. It applies the same priority order (env vars → programmatic config → defaults) and throws a descriptive error if a required key is missing.

```ts
import { getConfig } from '@workos-inc/authkit-react-router';

getConfig<K extends keyof AuthKitConfig>(key: K): AuthKitConfig[K]
```

### Example

```ts
import { getConfig } from '@workos-inc/authkit-react-router';

const clientId = getConfig('clientId');
const cookieName = getConfig('cookieName'); // 'wos-session' by default
```

<Note>
  `getConfig` is primarily intended for internal use within AuthKit. Prefer reading configuration from environment variables or calling `configure()` at app startup rather than reading individual keys at runtime.
</Note>
