---
title: "getWorkOS — Access the WorkOS Node SDK Client"
sidebarTitle: "getWorkOS"
description: "getWorkOS returns the configured WorkOS Node SDK client instance for direct access to organizations, user management, and other WorkOS APIs."
---

`getWorkOS` returns the shared `@workos-inc/node` client instance that AuthKit configures internally. Use it when you need to call WorkOS management APIs that aren't covered by AuthKit's higher-level helpers — for example, listing or creating organizations, fetching a user record directly, or performing any other WorkOS SDK operation from a loader or action.

The client is initialized lazily (on first call) using the same `clientId`, `apiKey`, `apiHostname`, `apiHttps`, and `apiPort` values that the rest of AuthKit reads from [configure](/api-reference/configure) or environment variables.

## Import

```ts
import { getWorkOS } from '@workos-inc/authkit-react-router';
```

## Signature

```ts
getWorkOS(): WorkOS
```

## Returns

<ResponseField name="WorkOS" type="WorkOS">
  The configured [`@workos-inc/node`](https://github.com/workos/workos-node) `WorkOS` client instance. The same instance is returned on every call (singleton). You can call any method available in the WorkOS Node SDK directly on this object.
</ResponseField>

## Example

### Listing organizations

```ts
import { getWorkOS } from '@workos-inc/authkit-react-router';

// Get the shared, configured WorkOS client
const workos = getWorkOS();

// Call any WorkOS SDK method
const { data: organizations } = await workos.organizations.listOrganizations({
  limit: 10,
});

console.log(organizations);
```

### Using in a React Router loader

```ts
import { type LoaderFunctionArgs } from 'react-router';
import { authkitLoader, getWorkOS } from '@workos-inc/authkit-react-router';

export const loader = (args: LoaderFunctionArgs) =>
  authkitLoader(args, async ({ auth }) => {
    if (!auth.user || !auth.organizationId) {
      return { organization: null };
    }

    const workos = getWorkOS();
    const organization = await workos.organizations.getOrganization(
      auth.organizationId,
    );

    return { organization };
  }, { ensureSignedIn: true });
```

<Warning>
  Management APIs require a WorkOS API key (`WORKOS_API_KEY` or `configure({ apiKey })`). In public-client (keyless) mode, calling management methods on the client — such as `workos.organizations.*` or `workos.userManagement.getUser` — causes the WorkOS Node SDK to throw an `ApiKeyRequiredException`.

  Feature flags (`getFeatureFlagsRuntimeClient`) also require an API key and throw with the message `"Feature flags require a WorkOS API key; set WORKOS_API_KEY or configure({ apiKey }). Public-client (keyless) mode supports sign-in only."` in keyless mode.

  See [Public client mode](/api-reference/configure#config-options) for the complete list of what works without an API key.
</Warning>

<Note>
  The `WorkOS` client instance is configured from the same source as the rest of AuthKit. Changing settings via [`configure`](/api-reference/configure) before the first `getWorkOS()` call ensures the client picks up those values. Because the instance is a singleton, settings changed after the first call do not affect the already-created client.
</Note>
